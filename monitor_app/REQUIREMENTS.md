# SteppingMotorDriver モニターアプリ 要求仕様書

## 1. 概要

### 1.1 目的
SteppingMotorDriver 基板（ESP32-S3、3軸ステッピングモーター制御、USB-CDC通信）と接続し、
PC 上から軸状態・エンコーダ・電流/電圧をリアルタイム監視し、モーション制御・パラメータ設定・
ログ記録を行うデスクトップアプリケーション。

RobotArm2 は 6 軸（J1〜J6）で構成されるが、本ドライバ基板は 3ch 仕様のため、
6 軸フル構成では **2 枚の基板を USB で同時接続**して運用する。本アプリはこの複数基板同時運用を
前提とする。

### 1.2 対象ファームウェア
- リポジトリ: `SteppingMotorDriver/firmware`
- 通信インターフェース: USB-CDC（テキストコマンドプロトコル、`\n` 終端）
- コマンド体系・応答フォーマット: [firmware/REQUIREMENTS.md Section 4](../firmware/REQUIREMENTS.md) 準拠
- 詳細プロトコルは本書では再定義せず、ファームウェア側 REQUIREMENTS.md を単一の正とする
  （本アプリはコマンド文字列を変更せずそのまま送受信する）

### 1.3 想定ユーザー
- 開発者本人（ファームウェアのデバッグ・チューニング・実機検証）
- 複数軸を同時に扱うロボットアーム調整作業（ホーミング、脱調確認、電流波形確認等）

| 項目 | 内容 |

## 3. 機能要件

### 3.1 接続管理（F-CONN）

#### F-CONN-01: シリアルポート一覧・選択

- 起動時および手動更新操作で、PC に接続されている COM ポート一覧を取得し表示する
- **VID/PID による一次分類**：ESP32-S3 内蔵 USB Serial/JTAG のデフォルト USB ディスクリプタ
  （VID=`303A`／PID=`1001`、Espressif標準値。本ファームウェアは `sdkconfig` で上書きしておらず
  デフォルト値のまま、要実機確認）に一致するポートを候補として強調表示する
  （`robot_arm_monitor` の `multi_i2c_bridge` 向け `VID_HINT` 方式、
  [design_spec.md §3.1](../../robot_arm_monitor/docs/design_spec.md) と同じ考え方）
- 候補外のポートも一覧には表示するが、候補と視覚的に区別する（VID/PID一致は絞り込みのヒントに過ぎず、
  接続自体は候補外ポートに対しても手動で行えることとする）
- ユーザーはポートを選択して個別に接続/切断できる

#### F-CONN-02: 複数基板同時接続
- 複数（2枚以上）の基板に同時接続できる。各接続は独立したシリアルセッションとして管理する
- 各基板接続に対しユーザーが識別名（例: "Board A (J1-J3)" / "Board B (J4-J6)"）を付与できる
- 識別名と基板固有ID（F-CONN-06）の対応、および軸オフセットはアプリ設定として保存し、次回起動時に復元する

#### F-CONN-06: 基板固有ID（Factory MAC）による識別・軸マッピング

**採用方針：** ESP32-S3 の factory MAC アドレス（eFuse、書き換え不可・グローバルユニーク）を
基板固有 ID として使用する（ファームウェア側 F-COM-05 準拠）。COM ポート番号は OS の再起動や
USB 抜き差し順序で変動するため、識別・軸マッピングの基準には使用しない。

- **接続前（デバイス列挙時）**：Node.js `serialport.list()` で取得できる USB ディスクリプタの
  `serialNumber` プロパティ（ファームウェアが `iSerialNumber` に設定する MAC 由来文字列）を用いて、
  シリアルポートを開く前に「どの物理基板がどの COM ポートに割り当てられているか」を**暫定的に**判定する
  （F-CONN-01 の VID/PID 候補と組み合わせて表示する）
- **接続後（疎通確認時）**：`PING` 応答確認後に `GET BOARD_ID` を送信し、`serialNumber` と一致することを
  検証する
- **不一致時の扱い（確定）**：`serialNumber`（USBディスクリプタ、接続前の暫定値）と `GET BOARD_ID`
  （ファームウェア応答、接続後の実測値）が一致しない場合、**`GET BOARD_ID` の値を正として扱う**。
  識別名・軸オフセットの対応表照合は `GET BOARD_ID` の値で行い、画面上には不一致であった旨を警告表示する
  （OSのUSBディスクリプタキャッシュが古い場合や、接続操作中に基板が差し替えられた場合を想定。
  ファームウェア側の実測値を信頼する方が安全側であるため、接続拒否はしない）
- ユーザーは初回接続時に「基板固有ID（MACアドレス）」と「識別名」「担当軸範囲（例: J1-J3）」を
  1 回だけ紐付ければよく、以降は COM ポートが変わっても自動的に同じ基板として認識される
- この対応表（MACアドレス ↔ 識別名 ↔ 軸オフセット）をアプリ設定として永続化する（F-CONN-02）
- `GET BOARD_ID` が `ERR E012` を返す機体（旧ファームウェア等）を検出した場合は、
  従来通り COM ポート手動選択によるフォールバック運用を許可する。
  **この場合の制約（明記）**：基板固有IDによる自動認識ができないため、識別名・軸オフセットの対応表は
  適用されない。COMポート番号は再起動・抜き差し順序で変動しうるため、**セッションのたびにユーザーが
  手動でポートと識別名を再確認する必要がある**（永続化された自動マッピングの対象外）。恒久的な運用では
  ファームウェア更新（F-COM-05対応版）を推奨する

#### F-CONN-03: 接続確立シーケンス
- 接続確立後、`PING` コマンドで疎通確認を行う
  （応答: `OK PONG` を期待。ファームウェア実装済みコマンド。応答が無い場合は接続失敗として扱う）
- 疎通確認後に `STATUS` コマンドを送信し、初期状態を取得する
- ボーレート: 115200 bps 固定（ファームウェア仕様準拠）

#### F-CONN-04: 切断・再接続
- ユーザー操作による明示的切断ができる
- USB 切断（デバイス側の抜去等）を検知した場合、当該基板の表示を「切断」状態にし、他基板の監視は継続する
- 再接続時は F-CONN-03 のシーケンスを再実行する
  （ファームウェア側の通信ウォッチドッグにより、再接続後は `STATUS` 送信のみでセッション再確立可能。ENABLE 不要）

#### F-CONN-05: 送受信ログ（デバッグ用）
- 各基板ごとに送受信した生コマンド・応答を時刻付きでコンソール表示できる（開発者向けデバッグビュー、開閉可能なパネル）

### 3.2 状態監視（F-MON）

#### F-MON-01: ポーリング方式によるステータス取得
- 各基板に対し `STATUS`（JSON応答、全軸サマリー）を一定周期でポーリングする
- ポーリング周期はユーザー設定可能とする（デフォルト 100 ms、範囲 50〜1000 ms）
- ハートビート（`EVT` 経由の非同期通知、ファームウェア F-COM-03）も並行して受信し、UI 更新のトリガーとして利用可能とする

#### F-MON-02: 軸ステータス表示
各軸（基板ごとに ch0〜ch2、複数基板時は横断的な軸番号にマッピング）について以下を表示する：

| 項目 | 取得元コマンド/イベント | 表示形式 |
|------|----------------------|---------|
| 軸状態（IDLE/SLEEP/ACCEL/CRUISE/DECEL/HOMING/FAULT） | `GET STATE <axis>` または `STATUS` | ラベル＋状態色分け |
| ステップ位置 | `GET POS <axis>` | 数値（steps） |
| エンコーダ位置 | `GET ENC <axis>` | 数値（カウント） |
| 現在速度 | `GET VEL <axis>` | 数値（steps/sec） |
| ステップ/エンコーダ偏差 | 位置・エンコーダ値から算出（`encoder_pos - step_pos`） | 数値＋閾値超過時の警告色 |

#### F-MON-03: ADC値表示
- 電流値（`GET ADC <ch>`、mA）、電源電圧（分圧換算後、V）を表示する
- 過電流閾値に対する現在値の割合をバー表示する

#### F-MON-04: フォルト情報表示
- `EVT FAULT <reason> <axis_mask>` 受信時に画面上に明確な警告表示（モーダルまたは常時表示のフォルトバナー）を出す
- `GET FAULT_INFO` により最後のフォルト理由・軸・発生時刻を表示する
- フォルト発生時、原因別（`ESTOP` / `OVERCURRENT` / `STALL`）に表示を切り替える

#### F-MON-05: 非同期イベントの表示
以下のイベントを受信し、イベントログパネルに時刻付きで一覧表示する（ファームウェア Section 4.5 準拠）：

`HOME_DONE` / `HOME_TIMEOUT` / `STALL_WARN` / `STALL_FAULT` / `OVERCURRENT` /
`MOVE_DONE` / `MOVE_ABORTED` / `SYNC_DONE` / `SYNC_ABORTED` / `LIMIT_HIT` / `COMM_TIMEOUT`

イベントログパネルには「エラー履歴取得」ボタンを設け、押下時に `GET LOG`（ファームウェア F-COM-06）を送信し、
接続前を含むファームウェア内蓄積分（最大24件）をイベントログへ追記表示できる。ライブ受信したイベントとは
`[履歴 boot+<秒>s]` 接頭辞で区別する（ファームウェアのタイムスタンプはブート起点のため壁時計に変換できない）。

#### F-MON-06: 全軸ダッシュボード
- 接続中の全基板・全軸の状態をひと目で確認できる一覧ビュー（サマリーテーブル）を提供する
- 軸単位の詳細ビュー（F-MON-02〜04 の内容をフォーカス表示）へ遷移できる

---

### 3.3 トレンドグラフ（F-GRAPH）

#### F-GRAPH-01: リアルタイム時系列プロット
- 以下の項目をリアルタイムの時系列グラフとして表示できる：
  - 軸ごとの速度（steps/sec）
  - 軸ごとのステップ位置／エンコーダ位置
  - 軸ごとのステップ/エンコーダ偏差（脱調傾向確認用）
  - 電流値（mA）
  - 電源電圧（V）
- 複数系列を同一グラフに重ね描画できる（例: 3軸の電流を1グラフで比較）
- 表示時間幅（ウィンドウ）をユーザー設定可能とする（デフォルト 60 秒、選択肢: 10s/30s/60s/300s）

#### F-GRAPH-02: 一時停止・カーソル確認
- グラフ描画を一時停止し、任意時点の値をカーソルで確認できる
- 一時停止中も内部バッファへのデータ収集は継続する（再開時に空白が生じない）

#### F-GRAPH-03: しきい値ライン表示
- 過電流閾値・脱調警告/フォルト閾値など、設定されているしきい値をグラフ上に基準線として表示する

### 3.4 モーション制御（F-CTRL）

#### F-CTRL-01: 基本操作コマンド発行
UI 操作から以下のコマンドを発行できる（対象軸・対象基板を明示的に選択する UI とする）：

| 操作 | 対応コマンド |
|------|------------|
| 有効化 / 無効化 | `ENABLE <axis>` / `DISABLE <axis>` |
| 通常停止 | `STOP <axis>` |
| コイル解除停止 | `STOP_FREE <axis>` |
| 緊急停止（全軸・当該基板） | `ESTOP` |
| フォルト復帰 | `CLEAR_FAULT` |
| ホーミング開始 | `HOME <axis>` |

#### F-CTRL-02: ジョグ操作
- 速度指定によるジョグ（連続回転）ボタン（正転/逆転、押している間 `VEL` を送信し離すと `STOP`）を提供する
- ジョグ速度はプリセットまたはスライダーで指定できる

#### F-CTRL-03: 目標位置移動
- 相対移動（`MOVE <axis> <steps>`）・絶対位置移動（`MOVETO <axis> <pos>`）を数値入力で発行できる

#### F-CTRL-04: 多軸同期移動
- 複数軸（同一基板内、2〜3軸）を選択し、各軸の目標ステップ数を指定して `SYNC_MOVE` を発行できる

#### F-CTRL-05: 緊急停止の集約操作
- 接続中の全基板に対して同時に `ESTOP` を発行する「全停止」ボタンをメイン画面の常時見える位置に配置する
  （複数基板運用時の安全機能として最優先で実装する）

#### F-CTRL-06: コマンド実行結果のフィードバック
- 発行したコマンドの応答（`OK` / `ERR <code>`）を UI 上に表示する
- `ERR` 応答時はエラーコード（Section 4.6 のコード一覧）に対応するメッセージを表示する

---

### 3.5 パラメータ設定（F-PARAM）

#### F-PARAM-01: 軸パラメータ編集
以下のパラメータを軸ごとに表示・編集できる（ファームウェア F-MOT-10 準拠）：

`v_max` / `accel` / `decel` / `max_pos` / `min_pos` / `idle_timeout_ms` /
`stall_fault_th` / `home_offset_steps` / `v_home_coarse` / `v_home_fine` /
`back_off_steps` / `comm_timeout_ms` / `home_dir`

- 対応コマンド: `SET VMAX` / `SET ACCEL` / `SET DECEL` / `SET SOFT_LIMIT` /
  `SET IDLE_TIMEOUT` / `SET STALL_FAULT` / `SET HOME_DIR` / `SET COMM_TIMEOUT` 等
- モーション実行中はファームウェア側が `ERR E004` を返すため、UI 側でも編集不可の状態表示を行う
  （実行中軸の設定欄をグレーアウトする）

#### F-PARAM-02: システム設定編集
- マイクロステップ設定（`SET MICROSTEP <div>`、全軸停止中のみ操作可能）
- ADC 移動平均窓サイズ（`SET ADC_FILTER <ch|ALL> <N>`）
- 過電流閾値（`SET CURRENT_LIMIT <axis> <mA>`）
- 電圧分圧比（`SET VOLT_DIVIDER <ratio>`）

#### F-PARAM-03: NVS 保存・読込・初期化
- `SAVE`（現在設定をNVSへ保存）
- `LOAD`（NVSから再読込）
- `RESET_CONFIG`（工場出荷デフォルトへ復帰、確認ダイアログ必須）

#### F-PARAM-04: パラメータの一括表示・比較
- 複数基板・複数軸のパラメータを一覧表で横断的に確認できる（設定ミスの発見を容易にする）

---

### 3.6 ログ記録・エクスポート（F-LOG）

#### F-LOG-01: CSV ロギング
- ユーザー操作でロギング開始/停止を切り替えられる
- 記録対象: 時刻（ISO8601 または経過ms）、基板識別名、軸番号、軸状態、ステップ位置、エンコーダ位置、速度、電流値、電源電圧
- 記録間隔はステータスポーリング周期（F-MON-01）に連動する
- ファイル出力先はユーザーが選択できる（デフォルトはアプリ設定で指定したディレクトリ）

#### F-LOG-02: イベントログのエクスポート
- F-MON-05 のイベントログ（発生時刻・種別・軸・付随データ）を CSV としてエクスポートできる

#### F-LOG-03: セッションファイル命名規則
- ログファイル名にはロギング開始時刻を含める（例: `motor_log_YYYYMMDD_HHMMSS.csv`）

## 4. 非機能要件

### 4.1 パフォーマンス
- 複数基板（最大想定 2〜3枚）同時接続時も、各基板 100ms 周期のポーリングを破綻なく処理できること
- グラフ描画はデータ蓄積量が増えても UI がフリーズしないこと（描画対象データ点数に上限を設け、古いデータは間引き/破棄する）

### 4.2 安全性
- 誤操作防止のため、`ESTOP` 以外の破壊的操作（`RESET_CONFIG`、複数軸へのモーションコマンド一括送信等）には確認ダイアログを設ける
- 通信切断時は当該基板に対する操作 UI を無効化し、誤って古い状態への操作を送信しないようにする
- ファームウェア側の安全設計（DRV_EN/SLEEP/RESET は全軸共通、FAULT はソフトウェア間接検知）を UI 上の注記として明示し、
  ユーザーがハードウェア制約を誤解しないようにする

### 4.3 可用性・堅牢性
- シリアル通信タイムアウトやパースエラー発生時にアプリ全体がクラッシュしないこと（該当基板の接続のみエラー状態にする）
- アプリ設定（COMポート割当、識別名、ポーリング周期、ログ出力先）はローカルに永続化し、次回起動時に復元する

### 4.4 保守性
- ファームウェアのコマンド/応答仕様変更に追従しやすいよう、コマンド文字列・パーサ処理は通信レイヤーに集約し、
  UI ロジックと分離する
- コマンドプロトコルの正はあくまで `firmware/REQUIREMENTS.md` とし、本アプリはそれに追従する

## 6. 制約事項

- 本アプリはファームウェアのコマンドセットを変更しない（プロトコル拡張が必要な場合は
  `firmware/REQUIREMENTS.md` の更新を先に行い、本書もそれに追従して改訂する）
- DRV_EN / DRV_SLEEP / DRV_RESET は基板単位で全軸共通のため、UI 上で「軸単位のスリープ制御」を
  暗示する表現・操作は行わない
- ファームウェアは FAULT ピンを直接検知できないため、本アプリの FAULT 表示は
  すべて間接検知結果（`OVERCURRENT` / `STALL` / `ESTOP`）に基づく
